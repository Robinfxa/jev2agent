# E0｜Codex 真机验收清单

**状态：NOT RUN。** 此文是实施验收要求，不是执行报告。原 14 项 [E0 条件](../references/closeout/evidence/E0.txt) 全量保留；因为本包主张同 run 的恢复连续性，H12 在这个 Codex 配置中也是必测项，不能标 N/A 获得通过。

## 1. 开始前锁定什么

记录 Codex CLI 实际版本、入口 hash、分发工件版本/校验、OS、MCP SDK/协议版本、provider build、原生配置 hash、可信 run manifest hash、工具 schema hash、真实任务/接收域绑定、模型请求观察位置、存储与隔离方案。`config/e0-evidence.template.json` 尚未填值，不能作为运行配置。

`tools/probe_host.py` 只做本机探测。版本字符串只能说明被执行入口返回了什么；脚本 hash 也不能代表它转调的所有二进制。分发锁必须补充对应安装来源/工件身份。探测脚本不读 `~/.codex`、token、浏览器账户或完整环境变量，不启动模型会话。

目标版本的真实启动方式、MCP 配置及可观测接口从安装包帮助、版本化官方文档/源码核验。当前没有联网核验任何 Codex 接口，不将早期讨论中的第三方安装示例当成当前支持矩阵。

## 2. 证据链

```text
固定且合法的 smoke 任务
→ srr_search 原始完整返回
→ provider 的封装信封与绑定
→ 真实下一次 Codex 模型请求中的工具输出
→ Codex 发出的 srr_recall 请求
→ 相同旧快照的原文响应
→ 后续真实模型请求
```

明确要求 Codex 做 recall 可以作为接入 smoke，不计作自然需求发现。provider stdout、普通终端显示、模型说“我读到了”都不能替代真实模型请求。需要 instrumentation 时，只在授权本地构建/调试环境观测实际出站构造，不访问账户凭据，不因无法观察就编造 SDK 字段。

所有原始记录只能在授权范围内采集；敏感内容可有受控原件与核对过的脱敏索引。哈希用于定位，不能证明脱敏覆盖充分或内容真实。审查者必须打开证据核对，而不只看文件名。

## 3. 必测项

| ID | 实际操作 | 通过证据 | 失败时 |
|---|---|---|---|
| H01 | `admission=off` 调用同一自有搜索 | 约定返回边界与全量工具状态、顺序、错误一致，无新延后 | 保持 off 并修边界；与原生 A 的整包差异仍计成本 |
| H02 | 在授权构造结果中延后一块 | 真实下一模型请求只有应披露内容；无 metadata、日志、第二字段重附全文 | 未能观察或发生泄漏都不通过 |
| H03 | 明确调用 recall | 真正工具路径取回同一 snapshot 字节，scope/版本正确，无二次筛选 | 停止发布新延后引用 |
| H04 | 注入 partial/unknown/错误 | 状态保留，不伪装 complete，无新语义调用 | 回原流程并记录错误 |
| H05 | 全文请求及运行器 Required Reads | protected 不进入 D；全文有真正可遍历读取路径 | 修保护；不能降级 H 换取预算 |
| H06 | 无效/超时/合法弃权 | 无效事件回允许 B；合法块弃权 keep/闭包；迟到结果不覆盖已回复 | 不得混淆两类失败 |
| H07 | 在响应提交前取消 | 无候选信封发布，迟到判断丢弃 | 修取消边界 |
| H08 | 发送中断或收件不明 | local written≠delivered；unknown 不盲发第二响应；有真实核对证据及 fail-stop 路径 | 无核对方法则此适配不验收 |
| H09 | 重复内部回调、合法新调用、连接重建 | 正确 invocation/run/channel 绑定；内部只回复一次；合法新调用不被全局 ID 去重吞掉 | 修映射，不许按 query 合并 |
| H10 | 改任务 epoch、撤权、伪造 agent/run 参数 | 旧选择不得提交；新读取拒绝；操作已交付不声称可撤回 | 修可信绑定，禁止新干预 |
| H11 | 关 C、关 admission、尝试不兼容升级 | 开关分离；旧合法引用继续；不兼容升级拒绝或排空 | 不删库假装回滚 |
| H12 | 同 run compaction、provider 重启/重连 | 目录可发现，旧源在同授权下可召回；不将新任务冒充旧 run | 此配置不能启用；不以“不支持压缩”跳过 |
| H13 | 配额满、事务失败、损坏源 | 无虚假 handle；无活跃源逐出；不可恢复错误显式 | 停新延后，保留最低证据 |
| H14 | 禁止后端外发 | provider 无远端语义调用；同权限原流程可用；网络边界实际生效 | 停 C；不能用“没填 API key”代替隔离 |

原 E0 的未编号输入隔离补充，在证据索引中以 **ISOLATION** 单独登记；这只是本包字段别名，不伪称原文有 H15。验收者要检查主模型、provider、selector、evaluator 的请求/挂载/工具通道，验证没有后见标签或隐藏测试泄漏。正常任务契约和原生读取仍必须可达。

H06 的 C 未部署部分允许用受控故障 adapter 验接口，但必须标 injected fault 而非真实语义模型结果；该检查不证明 C 质量。H14 要验证物理/运行器约束，不仅是程序自报布尔值。

## 4. 如何记状态

逐项使用 `NOT_RUN / FAIL / PASS`。本配置没有默认跳过项；变更支持范围必须重新裁定，不由脚本接受 N/A。每个 PASS 至少有一份实际 Codex trace/请求证据，包含 host/config/run 绑定、预期、观察、局限及审查者；数据可分文件存储并用摘要相连。

`tools/check_e0_evidence.py` **只检查资料结构与文件哈希**，不会理解 trace、识别伪造或替代人的集成判定。结构完整时它只输出 `READY_FOR_HUMAN_REVIEW`，不写 `E0 PASS`、不改开关。其测试中的结构性假文件也不是真实 Codex 数据。

当前模板全为 NOT_RUN，工具应拒绝晋升。即便将来 E0 通过，也只允许进入已授权实验，不代表 B 已胜 A 或 C 可以默认启用。
