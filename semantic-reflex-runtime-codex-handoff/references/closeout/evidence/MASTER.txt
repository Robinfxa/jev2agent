L0066 | ## 00 总纲：北极星、不变量与成书契约
L0067 | 
L0068 | ### 00.1 为什么做：改进整条任务路径，而不是再增加一个判断者
L0069 | 
L0070 | 拟议北极星：**在保留任务质量、既有权限及独立验收的条件下，降低现有 coding / multi-agent 工作流每个成功任务的实际执行成本。**
L0071 | 
L0072 | 这不是“让小模型替大模型想所有问题”。需要证明的具体机制是：在接收方首次读取之前，把一部分可选内容延后披露，能够减少输入或后续无效工作；有需要时可以取回原文，而且收益足以支付筛选、召回、返工与维护成本。
L0073 | 
L0074 | 项目同时保留轨迹监测假设：跨步骤观察可能发现单步判断看不出的停滞。但这一假设必须单独评测，不能由披露有效推导成立。
L0075 | 
L0076 | 因此，本书分开三个命题：
L0077 | 
L0078 | | 命题 | 需要证明什么 | 不能被什么替代 |
L0079 | |---|---|---|
L0080 | | 信息披露有用 | 完整任务结果在质量约束下更经济 | 单次输出缩短、分类准确率 |
L0081 | | 轨迹干预有用 | 干预后实际轨迹优于可比的不干预轨迹 | 检测到重复、给出高异常分 |
L0082 | | 通用 runtime 有用 | 多个已验证场景确有可共享合同且维护成本合理 | 架构图可以画在一起、predicate 名字相同 |
L0083 | 
L0084 | 首个实验仍只验证第一个命题。v0.2 为第二个命题补充独立设计与激活条件，不前移真实干预；第三个仍是未来需证明的抽象价值。
L0085 | 
L0086 | ### 00.2 为谁做，以及不假定什么
L0087 | 
L0088 | 首批使用者是现有 coding 工作流的维护者；直接消费者是主 agent、工具包装层与被授权的接收方。用户不必每轮介入，但明确给出的任务、权限和验收要求持续有效。
L0089 | 
L0090 | 本轮不假定某个宿主已支持任意 hook，不假定可以读取模型隐藏思维链，不假定所有工具结果都能拦截，不假定多 agent 一定比单 agent 划算。真实客户画像、付费意愿和需求规模均未验证。
L0091 | 
L0092 | 首发工作假设：**在一处可控的只读搜索工具返回边界实现局部 ADMIT + 原文 recall**。这不是宿主选型结论，更不是已实现插件。
L0093 | 
L0094 | ### 00.3 本轮最重要的认识修订
L0095 | 
L0096 | **“没有终局裁决权”不等于“没有实际影响力”。** 语义层虽不能宣布 complete，但如果它能让 agent 永远看不到反例，就能改变后者的判断。因此，披露权也必须是受约束、可审计的权力。
L0097 | 
L0098 | **“可召回”不等于“会召回”。** agent 不知道被省略了什么，可能不会主动请求。设计必须同时保留可发现的延后目录，并让独立评测检查未被召回的关键遗漏；不能把低召回率自动解释为筛得好。
L0099 | 
L0100 | **“在推理前发生”不等于“经济上值得”。** 筛选仍要读取状态和内容。默认旁路、只对可覆盖收益的场景启用，比每次调用小模型更合理。
L0101 | 
L0102 | **“证据可回溯”不等于“结论正确”。** 原文完整和 hash 校验只能证明保真，不能证明选择适当。来源合同与效果评估必须分开。
L0103 | 
L0104 | 以上均为本轮推导，论证和反例见[离线设计审查](../research/2026-09-18-offline-bull-bear.md)。
L0105 | 
L0106 | ### 00.4 推荐不变量
L0107 | 
L0108 | | ID | 不变量 | 主定义 / 验证位置 |
L0109 | |---|---|---|
L0110 | | I01 | 不接管模型执行循环、沙箱、权限审批和最终验收；宿主仍为相应权威 | §03、§14 |
L0111 | | I02 | 只处理被明确授权为可筛选的 soft result；Hard Context 和明确全文请求不被语义层降级 | §04、§08、§14 |
L0112 | | I03 | 延后的是本次披露，不是源证据；承诺可召回前必须保存相应授权快照 | §04、§09 |
L0113 | | I04 | 内容不完整、事件缺失和数据失效必须显式表达；未观察到不等于没有发生 | §03、§04、§11 |
L0114 | | I05 | 权限拒绝不因 fallback 或 recall 而绕过；外部后端也要通过独立数据传输授权 | §14 |
L0115 | | I06 | 新内容首次进入时处理；不主动重写已提交历史或动态重排稳定工具定义 | §08、§13 |
L0116 | | I07 | 不确定时可以保留或放弃筛选；分数不是正确率，后端不直接执行动作 | §05–§06 |
L0117 | | I08 | 不用另一轮完整理解替代廉价筛选：状态与判断有独立预算，无法经济处理则旁路 | §05、§13 |
L0118 | | I09 | 运行策略只用该事件时点之前的授权信息；离线后见证据不得泄漏回在线输入 | §11–§12 |
L0119 | | I10 | 削减 token、命中率、与 Director 一致率均不替代独立任务验收 | §12 |
L0120 | | I11 | 关闭特性时，在约定工具返回边界与基线一致；不把模型输出随机性算作此合同 | §03、§12 |
L0121 | | I12 | 必要原文/最小决策记录无法保存时，不继续生成依赖它们的延后披露 | §04、§11、§14 |
L0122 | 
L0123 | 这些是待评审的约束集合。其满足情况须靠契约测试与真实接入验证，不能靠提示词声明保证。
L0124 | 
L0125 | ### 00.5 目标函数：质量约束先于省钱
L0126 | 
L0127 | 对同一预先定义的任务集合、验收口径和资源预算，定义：
L0128 | 
L0129 | `单位成功任务执行成本 = 所有尝试的执行成本总和 / 独立验收成功任务数`。
L0130 | 
L0131 | 分子包含失败尝试与返工，不只统计成功运行；无成功任务时该指标无定义，不报告一个漂亮的平均值。人工介入分钟、端到端延迟、开发维护费用另列，只有明确单价和口径后才换算合并。
L0132 | 
L0133 | 目标可写成：在权限与硬合同不被破坏、质量满足预先冻结的约束、尾延迟可接受的前提下，最小化执行成本。样本成功率持平不证明真实成功率不退化；unknown 还需按 §12.15 分析缺失识别范围，不能两臂一律按失败即视为保守。允许退化幅度、置信判据和严重错误停止规则必须在闭环实验前确定。合同/权限违规不能以平均质量改善抵消。
L0134 | 
L0135 | 来源中提出了 Cost per Successful Task，但把不同量纲并列的概念式不直接拿来算账。本书按 §13 拆账；这是本轮明确的规范化，不是原文已经给出该计费公式。[D2：指标与工程目标](../../references/discussions/D2-runtime-kernel-cache.md)
L0136 |

L0153 | ## 01 系统画像：附着于宿主的信息披露与轨迹观察层
L0154 | 
L0155 | ### 01.1 两条逻辑路径，不一定两个服务
L0156 | 
L0157 | **在线路径**只使用当前已知、获授权的信息，并受严格成本与延迟预算限制。**离线评测路径**可在授权范围内检查完整来源、最终结果和后续反例，但不能把这些未来信息倒灌给在线策略。
L0158 | 
L0159 | ```text
L0160 | 宿主：任务 / 权限 / agent loop / tools / 最终验收
L0161 |   │
L0162 |   └─ 已覆盖的只读工具返回（尚未进入接收方 context）
L0163 |         │
L0164 |         ├─ 不合适或功能关闭 ──────────→ 原流程
L0165 |         │
L0166 |         └─ 完整性与授权检查 → 保存源快照 → 原文分块
L0167 |                                       │
L0168 |                                State Capsule
L0169 |                                       │
L0170 |                             规则基线 / 可选语义信号
L0171 |                                       │
L0172 |                                 Policy Engine
L0173 |                                       │
L0174 |                           Disclosure Envelope
L0175 |                     保留原文 + 延后目录 + recall 入口
L0176 |                                       │
L0177 |                                接收方 agent
L0178 |                                       │
L0179 |                       原文 recall：鉴权 → 取快照 → 追加
L0180 | 
L0181 | 事件与交付收据 ──→ 过程记录 ──→ 离线回放 / 独立验收
L0182 | 完整授权来源 ─────────────────→ 漏证据检查
L0183 | ```
L0184 | 
L0185 | 这里的“在线”指实际执行路径，不要求联网；“离线”指与生产干预分离的回放或评测，也不暗示后台持续工作。
L0186 | 
L0187 | ### 01.2 最小逻辑构件
L0188 | 
L0189 | | 构件 | 责任 | 明确不负责 |
L0190 | |---|---|---|
L0191 | | Host Adapter | 证明捕获与交付位置；声明覆盖；透传身份和权限 | 伪造全局支持、决定任务完成 |
L0192 | | State Capsule / Source Store | 冻结当前已知状态与源内容；维护来源和快照 | 替 agent 重做根因分析、建立通用长期记忆 |
L0193 | | Predicate Backend | 给出窄判断及弃权；引用真实块 | 直接修改上下文、授予权限 |
L0194 | | Policy Engine / Executor | 合并保护约束、信号、预算，生成并交付信封 | 发明事实、越过 must-keep |
L0195 | | Recall | 按当前权限取回特定旧快照 | 默认重跑工具、静默返回新版本 |
L0196 | | Telemetry / Evaluation | 分别记录发生了什么与实验结果 | 以一个自评分替代独立验收 |
L0197 | 
L0198 | 首版可用同进程函数、轻量文件或已有宿主存储承载；不预设多个 daemon、数据库或消息总线。逻辑隔离不等于物理多库，ValueHermes 的三库布局在本项目不直接继承。
L0199 | 
L0200 | ### 01.3 生命周期 × 构件总览
L0201 | 
L0202 | | 生命周期 | 对应能力 | 首批状态 | 关键边界 |
L0203 | |---|---|---|---|
L0204 | | 任务开始 / subagent 准备 | DISCLOSE | 后置设计 Draft | 不替换用户与任务合同 |
L0205 | | 已支持工具完整返回 | ADMIT | 推荐首发 | 必须发生在首次读取前 |
L0206 | | subagent 返回 | ADMIT 的另一适配面 | 后置 | 先优化报告合同，再证明额外筛选收益 |
L0207 | | 请求既有原文 | Recall | 首发必要合同 | 一次请求取回，不被同一语义层再次挡回 |
L0208 | | 请求尚未取得的新信息 | EXPAND | 后置 | agent 说明需求，检索负责发现候选 |
L0209 | | 多步事件累计 | OBSERVE | 后置设计；先验证事实与检测 | 看不到隐藏思维；不把未知判成停滞 |
L0210 | | 用户申请完成 / Director 验收 | 现有宿主工作流 | 不改 | 语义层不能自行宣布完成 |

L0215 | ### 01.4 接收方视图不是系统证据全集
L0216 | 
L0217 | 一个源结果可以被主 agent 与 subagent 分别读取。源快照不因为 A 已经见过而删除；“重复”应相对于当前接收方、当前已提交视图和版本判断。B 未读过的关键内容不能因为 A 读过而被系统级去重隐藏。
L0218 | 
L0219 | 同样，完整源证据不等于每个接收方都能读取：快照、目录和召回都必须遵守各自权限。不能通过目录泄漏无权获知的路径、标题或数量。
L0220 | 
L0221 | ### 01.5 示例：搜索结果尾部包含关键反例
L0222 | 
L0223 | **构造情景，不是实测**：agent 正调查 refresh state，搜索结果中大量命中缓存模块，尾部少量命中某后台 writer。按当前假设相关性排序，后者可能被延后。
L0224 | 
L0225 | 本书不声称通过一个 `must_keep` 分类器就能发现所有反例。正确的合同是：保留已明确声明的必读证据、完整搜索范围与返回状态；未披露内容有可枚举目录；允许无语义审批的原文取回；独立验收从完整来源检查是否漏掉 writer。若策略仍经常隐藏关键反例，就判失败，而不是给筛选器再叠一个筛选器。

L0229 | ## 02 宿主能力与复用取舍
L0230 | 
L0231 | ### 02.1 采用顺序
L0232 | 
L0233 | 继承材料中的优先顺序：**Harness-native → Static instructions → Deterministic policies → Semantic Reflex → Frontier reasoning**。这是一条取舍原则，不是所有宿主都已具备完整能力的事实声明。[D3：宿主与语义层分工](../../references/discussions/D3-runtime-stories.md)
L0234 | 
L0235 | 新增能力需要回答：原生或规则方案已做到什么；剩下什么语义缺口；能够避免哪笔下游成本；怎样独立证明不损害质量。
L0236 | 
L0237 | ### 02.2 首发载体推荐
L0238 | 
L0239 | 推荐先用**一处受控只读工具包装边界**。它能把“我们有没有在读取前处理内容”变成局部可测试合同，而不必先宣称支持所有 hooks。
L0240 | 
L0241 | 选择它的代价必须接受：原生 shell、未包装的工具、流式通道及 subagent 可能绕开它。首版报告实际覆盖比例，不把局部成功外推成全局收益。不为增加覆盖而悄悄禁用其他工具；那会成为另一项干预，须重新做基线。
L0242 | 
L0243 | 这只是接入策略，尚未决定 Codex、Claude Code、Hermes 或其他具体宿主；当前资料不能证明其现行版本提供所需控制点。
L0244 | 
L0245 | ### 02.3 本轮复用取舍摘要
L0246 | 
L0247 | | 能力 | 推荐取舍 | 理由 / 剩余证据 |
L0248 | |---|---|---|
L0249 | | agent loop、session、权限、sandbox、验收 | 复用宿主 | 不属于本项目优化对象；实际接缝待核 |
L0250 | | 工具输出结构、原生分页/按需读取 | 优先复用并纳入强基线 | 可能已解决大部分问题，不能用弱基线证明自己 |

L0260 | ### 02.4 Bull / bear 之后保留的承诺
L0261 | 
L0262 | 不是“语义层总能更优秀”，而是一个更弱、也更可验证的承诺：**在定义清楚的一类任务和接入边界内，实验能够分辨语义层的额外收益、质量损失和不适用范围。**
L0263 | 
L0264 | 若只能改善极少且原本廉价的案例，不扩建平台；若大多数收益来自规则，保留规则；若只有少数高成本场景有效，就定位为专项能力，不强行“通用化”。
