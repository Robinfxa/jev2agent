## PATCH-01｜拆开设计批准与验证状态

来源：[M17，L40–42](evidence/M17.txt)。对照原计划：[PLAN，L245–259](evidence/PLAN.txt)。

**原文**

> 技术章可以成为完整 Draft，但没有用户逐项评审、真实接入和实验结果，不能标 Accepted 或 Verified。本轮新增可执行合同实验是设计自检，不是正式宿主 Runtime 实现。

**建议替换**

> 设计状态与验证状态分开登记。Draft 是草案；Reviewed 说明明确范围的评审已执行，并注明评审者及其独立性；Accepted 仅表示项目负责人已批准该范围的设计基线，不表示实现或收益通过。Verified 必须绑定具体对象、宿主/配置版本、测试范围和实际证据。宿主无关合同可先单独提交设计批准；首个宿主的可行性阻塞仍保持开放，未核验前不得标记适配方案完成，也不得据此宣布整个首发架构阶段归档。本地合同实验仅为设计自检，不构成宿主或效果验证。

**影响：** 可以批准已评审的逻辑合同，但不能跳过宿主可行性；用户并未在本轮预先批准所有技术选择。本轮将作者侧核对标 Reviewed，不冒充独立工程验收。Validated/Verified 的对象与范围必须另记。

## PATCH-03｜使 Kernel 摘要服从唯一故障路由

来源：[M05，L45–51](evidence/M05.txt)；权威路由：[M06，L84–99](evidence/M06.txt)；结构要求：[M04，L92–98](evidence/M04.txt)。

**原文**

> 单块判断只能表达它在给定信息下的优先级，不能证明删除其他块不会影响联合解释。定义、例外、调用位置跨块关联时，优先保留确定性结构组；结构关联未知或组超预算时回基线，不偷偷只传一半证据。

**建议替换**

> 单块判断只能表达它在给定信息下的优先级，不能证明延后其他块不会影响联合解释。定义、例外、调用位置跨块关联时，优先保留确定性结构组；具体弃权、结构闭包和溢出退出统一按 §06.11。事件级不可用可回允许的 B/A；合法块级弃权先保留及求闭包，保护/弃权闭包超预算不能回到会延后该证据的 B。结构关联无法可靠确定时，不把未知当独立，也不生成无法证明结构完整的延后信封；使用满足原约束的原生完整读取或明确分页路径，否则诚实退出。

**影响：** 摘要不再暗示“组超预算一律 B”。这是对现有保护与退出规则的澄清；没有新增另一个策略引擎，也没有宣称真实运行出现了这类事故。
