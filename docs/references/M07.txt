L0010 | 
L0011 | ## 1. 运行故事与前置条件
L0012 | 
L0013 | 收到可信任务 brief → 解析不可降级的 Required Reads 与权限 → 从已授权原生目录取得候选 → 原生发现/确定性排序 → 可选窄语义优先级 → 追加初始资源 → 留下未选目录和读取入口。
L0014 | 
L0015 | 前提是目录真实存在、描述版本可追踪、资源正文可按原权限取回，并能证明插入发生在该接收方首次需要它们之前。目录缺失不是建设全仓库索引的自动理由；可以先使用原生检索与既有 brief。
L0016 | 
L0017 | ## 2. 合同与唯一归属
L0018 | 
L0019 | 输入消费 §04 的接收身份、任务合同、决定上下文版本与保护引用。输出复用 §08 的披露语义，但 `universe` 必须明确为**本次已枚举候选目录**，不是所有可用能力或所有相关文件。
L0020 | 
L0021 | 本章拥有 `InitialDisclosureRequest`：任务/接收身份绑定、触发原因、目录版本、候选作用域、Required Reads 引用与预算配置。目录卡片只表达生产方的描述，不视为已验证正文；正文获取和 hash/版本归 §04、读取权限归 §14。
L0022 | 
L0023 | 输出不得把“未选中工具名称”转成禁止调用。宿主权限约束与模型注意范围是两件事。新增权限限制属于另一个变更，不可暗藏在披露机制里。
L0024 | 
L0025 | ## 3. 首选机制与备选取舍
L0026 | 
L0027 | | 机制 | 推荐用途 | 不具备的保证 |
L0028 | |---|---|---|
L0029 | | 优化 Task Brief / Required Reads | 需求稳定、必读路径清晰 | 不能判断每个动态任务的新需求 |
L0030 | | 原生 discovery / metadata 检索 | 已有可用目录和按需读取 | 具体宿主效果仍待核验 |
L0031 | | 确定性分组与排序 | 命名、角色、路径关系明确 | 不等于语义最相关 |
L0032 | | 可选语义 rerank | 前三项之后仍存在有成本的歧义 | 不保证不漏反例，不能共享 ADMIT 阈值 |
L0033 | 
L0034 | 首版不会为了让候选更好排序而调用另一个大模型为全部文件写描述。描述生产与更新同样是成本；没有数据支持就保持简单。
L0035 | 
L0036 | ## 4. 缓存与接收方边界
L0037 | 
L0038 | 只使用经过核验的 append/原生加载路径；不把“允许调用范围”和“已缓存工具定义”当成相同宿主字段。未核验前不写任何厂商 API 名为已支持。
L0039 | 
L0040 | Subagent 有独立身份和视图。父 agent 见过某文档不等于子 agent 已见；也不自动授予子 agent 权限。父 brief 的明确引用是候选来源，不是越权读取许可。
L0041 | 
L0042 | ## 5. 失败与恢复
L0043 | 
L0044 | Required Reads 取不到：由既有任务流程说明阻塞，不以类似候选代替。目录版本不确定：降级原生发现，保留 unknown。语义选择超时：返回原生/确定性候选。工具定义需要重写稳定前缀：首个路径不启用该机制。
L0045 | 
L0046 | 显式要求全文时直接读取，原文 recall 不经重排。初始目录所指资源如果更新，必须分清“读取当前资源”与“取回旧快照”；只有后者适用 recall 合同。
L0047 | 
L0048 | ## 6. 独立验证与激活条件
L0049 | 
L0050 | 比较优化 brief + 原生 discovery 与相同目录上的语义选择；计入目录生成/更新、分类、正文读取和后续补读费用。主指标仍为完整任务质量与成本，找到第一个正确文件的时间只是诊断。
L0051 | 
L0052 | 构造反例包括过期描述、同名工具、任务所需资源不在候选中、子 agent 权限更窄、Required Reads 超预算。只在新增收益和接入均被独立证明后启用，不由 ADMIT 成功自动激活。
